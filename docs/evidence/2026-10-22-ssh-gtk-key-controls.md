# Native GTK SSH key controls

## Changed

The Native Management Center now exposes shared SSH key fingerprint inventory, public-key enrollment, and fingerprint-based revocation controls when the managed SSH resource is selected. Enrollment accepts exactly one bounded public-key line; revocation accepts a SHA256 fingerprint. Both paths use the shared management service, show the impact on owner-managed port 8022 and Ternuxx port 8023, require a preview and explicit confirmation, and refresh the key inventory after a successful apply. The existing service rejects removal of the last valid key and revalidates exact before/after hashes.

Changed source:
- `apps/management-center/management-center.c`
- `scripts/management_desktop_bridge.py`
- `tests/test_management_desktop_bridge.py`

The GTK bridge accepts only the fixed typed preview/apply actions. It does not expose arbitrary commands or private-key handling. The public key is non-secret and is passed to the local bridge process for the shared service call. No private key is accepted or generated by this flow.
