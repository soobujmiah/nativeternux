### W7k - isolate per-session graphics environment from shared PRoot profile

Confirmed in Native proot-distro 5.9.0 source: every normal Debian login calls inject_termux_profile() with child_env and rewrites the shared guest /etc/profile.d/termux-profile.sh. Ternuxx currently passes backend-specific --env values, so a VirGL login can persist GALLIUM_DRIVER=virpipe/VTEST_SOCKET_NAME while Zink sessions expect the shared profile to describe Zink. Simultaneous logins can race on this shared generated file, and later su - shells inherit whichever backend was written last.

Implement only in Ternuxx Native launch code: maintain one stable shared-profile baseline (Zink plus display/audio endpoint) for every Ternuxx Debian login; move backend-specific environment to the actual process command. For a default interactive shell, preserve the selected guest account's login shell and profile startup, then start the interactive shell with per-session environment overrides after profile loading. For explicit commands, prepend a guest /usr/bin/env with the selected backend environment. Do not patch proot-distro, edit the guest profile directly, or change the rootfs as part of source implementation.

Files likely: lib/launch.sh, lib/proot_diagnostics.py (safe login-shell lookup from the selected rootfs passwd entry), tests/test_launch_commands.py, tests/test_proot_diagnostics.py, docs/PROOT-GPU.md, docs/architecture/PROOT-SESSIONS.md, and this evidence record.
