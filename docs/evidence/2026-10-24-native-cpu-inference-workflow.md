## Implemented workflow

Ternuxx now provides one CPU-only model path through `tx ai`, the shared management service, TUI, authenticated loopback Web UI, and GTK management center. The service operations are `inference.cpu.status`, `inference.cpu.model.preview`, `inference.cpu.model.apply`, and `inference.cpu.run`; the clients call the same `lib/cpu_inference.py` implementation.

The supported model is `ggml-org/Qwen3-0.6B-GGUF` Q4_0, file size 428,970,080 bytes, Apache-2.0, SHA-256 `da2572f16c06133561ce56accaa822216f2391ef4d37fba427801cd6736417d4`. The source [model file page](https://huggingface.co/ggml-org/Qwen3-0.6B-GGUF/blob/main/Qwen3-0.6B-Q4_0.gguf) reports that size, license, and hash. Downloads use the model's official Hugging Face resolve URL and are rejected unless both exact size and SHA-256 match.

Model install and removal require a fresh deterministic preview ID and an exact client confirmation. Installation checks free storage, downloads to a private temporary file, verifies the artifact, fsyncs it, and renames it into `$TERNUXX_STATE_DIR/models/` with mode `0600` under a private (`0700`) directory. A private process lock serializes download, inference, and removal. A later install removes only safe Ternuxx-named partials left by a crashed download. Invalid existing files are preserved. Termux continues to own the `llama-cpp` runtime package; Ternuxx displays a package-manager simulation command and never installs or removes that package.

Inference uses the fixed local model, four CPU threads, a 512-token context, `-ngl 0`, deterministic seed/temperature, a one-line prompt capped at 4096 UTF-8 bytes, at most 128 output tokens, and a 120-second timeout. It places `$PREFIX/lib` before inherited loader paths and removes `LD_PRELOAD` for the child. Timeout or Ctrl-C targets only that inference process group. Prompts are passed to the CLI child without a shell; the bridge accepts prompt input on stdin, and the Web API keeps only a request fingerprint in its idempotency store.

## Verification

- Unit coverage exercises deterministic/read-only preview, exact confirmation, SHA and size mismatch, cancellation cleanup, insufficient disk, private file modes, symlink rejection, safe stale-part recovery, serialization against remove, CPU-only bounds, prompt framing, and process-group timeout handling.
- Shared service, capability, Web authorization/idempotency, TUI guided-action, GTK bridge, and GTK source-contract tests cover the cross-client contract.
- `clang -fsyntax-only -Wall -Wextra apps/management-center/management-center.c $(pkg-config --cflags gtk4)` passed. The extracted Web script passed `node --check` with `LD_LIBRARY_PATH="$PREFIX/lib"`.
- A live shared-service status call found Termux `llama-cpp 0.7.0` and the pinned model. A live shared-service run with `-ngl 0` returned exactly `NATIVE_CPU_OK`; it exited 0. The active Native display `:1`, supervisor, X11, XFCE, and audio owner were still reported running afterward.
- A follow-up three-run CLI repeat using the same deterministic 32-token CPU prompt returned `NATIVE_CPU_OK` each time, with exit 0 and wall times 3.154, 3.144, and 3.211 seconds. The maximum child-process RSS reported across the repeat was 550,408 KiB. Read-only CPU thermal readings were 45.279 °C before the repeat and 45.150 °C after it; SoC readings were 53.0 °C at both samples. These two endpoint readings do not establish sustained thermal stability or absence of throttling. The machine-readable result is in [repeat smoke data](data/2026-10-24-native-cpu-repeat-smoke.json).
- The device model hash matched the pinned SHA-256; the file was mode `0600` and its directory mode `0700`. No runtime package transaction was performed in this workflow. The package and model were installed earlier for the manual candidate test recorded in the [candidate audit](2026-10-24-native-cpu-inference-candidate-audit.md).

## Limits and next gate

This is a bounded first product workflow, not broad CPU inference support. It supports one small model and one foreground prompt at a time; it has no streamed tokens, multi-turn history, model registry, runtime package lifecycle, clean-install replay, or model-quality evaluation. A twenty-run monitored repeat also returned `NATIVE_CPU_OK` on every exit-0 run. The sequence took 63.339 seconds total, individual calls took 3.129–3.218 seconds, and peak child RSS was 550,008 KiB. The CPU thermal zone rose from 45.944 °C to 48.179 °C; the SoC zone read 55.0 °C throughout. The 60 °C stop guard was not reached; it was a conservative test guard, not an OEM limit. This is bounded one-minute-scale evidence, not a prolonged soak or thermal-throttling qualification. The [raw twenty-run record](data/2026-10-24-native-cpu-20-run-thermal.json) preserves each sample; the earlier [ten-run record](data/2026-10-24-native-cpu-long-repeat.json) remains available. A fresh continuation check on 2026-10-24 again returned `Operation not permitted` for `unshare -n true`; no inference process was launched under an isolated namespace. Network isolation remains unverified: Android denied `unshare -n` with `Operation not permitted`; a process-scoped seccomp probe successfully denied IPv4/IPv6 socket creation, but the actual `llama-cli` workflow exited 1 with `failed to get a free port`. No device network setting changed, and this failure is not offline-use evidence. A second filter that denied network egress syscalls timed out after 120 seconds and left a test-owned `llama-cli` child; that child was manually terminated and verified absent. These experiments are not offline-use evidence. A separate one-second timeout test without seccomp returned the expected timeout error and left no inference process behind. Full details are in [network isolation probe data](data/2026-10-24-native-cpu-network-isolation-probe.json). The manual candidate audit's two-run benchmark is a dated snapshot, not a product performance promise. GPU inference and NPU execution remain unimplemented. The model and runtime notices are recorded in [third-party notices](../readiness/THIRD-PARTY-NOTICES.md); source provenance and release review remain open, and the repository has no selected project license.
