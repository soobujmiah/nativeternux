# PRoot GUI apps in the native Termux:X11 desktop

The supported single-app path runs an individual GUI application from the installed Debian PRoot as a window in the already-running native Ternuxx XFCE session. Both native Termux and PRoot applications use the same X server and Activity. Switching Android apps or XFCE workspaces does not stop either environment.

```sh
# Opens Debian's XFCE Terminal in the current native desktop
xgo

# Or start a chosen PRoot GUI application
xgo thunar
xgo xmessage 'Hello from Debian PRoot'
```

The shell entrypoint is `~/x.sh`; it delegates to `scripts/proot-x11-app.sh`. The helper reads the active native display from `ternuxx status`, checks that its X11 socket is available and that the Debian guest can connect, then runs only the requested guest command. It does not start or stop X11, XFCE, PulseAudio, or another GUI session. Close the individual PRoot application's window to end that app. The `killx` alias is informational and no longer kills every X11/audio process or deletes display sockets.

The shared management service provides the provider-aware catalog and operations:

```sh
./ternuxx management shortcuts list
./ternuxx management shortcuts plan add files
./ternuxx management shortcuts apply add files --plan-id PLAN_ID --yes
./ternuxx management app launch files
```

The add/remove helper asks for confirmation after showing the exact target. The X11 shortcut manager uses the same service and displays a confirmation dialog before menu changes. Generated desktop entries call `management app launch`, which dispatches only catalog IDs. Removing a launcher never closes a running app or stops X11/XFCE. Existing user-edited or unrecognized launchers are reported as conflicts and left untouched; exact legacy entries generated by the previous helper can be updated safely after confirmation. The older `xgo` path remains available as an advanced CLI compatibility launcher.

`db` and `droot` remain the existing Debian shell-entry aliases. The old `x.sh` and GUI alias definitions are backed up with mode 0600 under `~/.local/share/ternuxx/legacy-backups/2026-10-18/`.

This opens PRoot applications inside the native XFCE desktop; it does not create a second full XFCE desktop. On 2026-10-18 the owner visually confirmed the PRoot `xmessage` window on native display `:1`. This proves an individual PRoot X11 client can render there. The owner later confirmed the Thunar window was also visible; a full second XFCE desktop remains unverified. A nested full desktop would need a nested X server such as Xephyr, which is not installed in the inspected guest. Installing additional Debian packages remains preview-first and is not part of this workflow.

The Android dual-app Termux:X11 profile (user 999) is deferred. Its Activity did not show the PRoot GUI in the owner test; the native shell also cannot control or inspect that profile across Android users. See the historical [display 0 experiment](PROOT-GUI-DISPLAY0.md).

## Device check — 2026-10-18

The owner confirmed the PRoot `xmessage` probe appeared on native `:1`. A later PRoot Thunar launch was visually confirmed by the owner while native supervisor, X11, and XFCE remained running. The menu manager has since been moved to the shared management service. Its read-only inventory preserves customized/unrecognized existing entries as conflicts; no launcher was changed during this repository verification.
